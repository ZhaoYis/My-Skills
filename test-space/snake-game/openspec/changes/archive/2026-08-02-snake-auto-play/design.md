## Context

贪吃蛇游戏为单文件前端应用（`index.html`，~5179 行），采用 Canvas 2D 渲染引擎和 `requestAnimationFrame` 游戏循环。欢迎界面已有迷你 AI 蛇（`miniGetAIDirection`）作为装饰，使用简单的墙壁规避和随机转向算法。但迷你 AI 不感知炸弹、道具、护盾等主游戏系统。

本次变更引入主游戏的挂机模式 AI，核心原则是 **AI 仅替换方向输入源**——`nextDirection` 的来源从用户按键切换为 AI 决策函数，所有现有系统（碰撞、道具、炸弹、计分、排行榜）行为不变。

## Goals / Non-Goals

**Goals:**
- 在经典和计时两种模式下，AI 能够自主控制蛇移动，处理炸弹和道具
- 提供便捷的开关机制（开始界面 + H 键），方便开发测试
- 用户随时通过方向键取回控制权
- 挂机成绩在排行榜中透明标注

**Non-Goals:**
- BFS/A* 全图寻路算法（代码膨胀大，与项目风格不符）
- 挂机专属难度预设
- 游戏回放/录制功能
- 排行榜"隐藏挂机成绩"筛选按钮
- 移动端挂机支持

## Decisions

| 决策 | 选择 | 理由 | 替代方案 |
|------|------|------|---------|
| AI 算法 | 加权评分 + 一步前瞻 + 洪水填充 | 代码量少（~80 行），与现有迷你蛇 AI 风格一致；一步前瞻足以处理炸弹威胁 | BFS 全图寻路：复杂度高，代码膨胀大 |
| 方向保持策略 | 80% 概率保持当前方向 | 减少运动抖动，外观更自然 | 每帧重新评估：蛇运动会频繁转向，不自然 |
| 用户接管方式 | 方向键立即退出挂机 | 最自然的交互——用户不需要额外的"退出"步骤 | 需要先关闭再输入：多一步操作 |
| 排行榜策略 | 正常计入，`result` 加 `:auto` 后缀 | 非破坏性——不改变解析逻辑；UI 渲染时显示 🤖 | 单独存储或完全排除：增加数据层复杂度 |
| 挂机状态持久性 | 跨局保持（再来一局不清除） | 减少重复操作；开发者可连续测试 | 每局重置：每次测试需重新开启 |
| 空间评估方法 | 简化洪水填充（深度限制 50） | 防止走入死胡同；深度限制避免性能问题 | 不做空间评估：AI 可能在长蛇身时困住自己 |
| UI 风格 | 与现有设置面板风格一致 | 视觉统一，降低用户学习成本 | 全新设计语言：不必要 |

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|---------|
| 极长蛇身（如蛇身 >100 节）时 AI 可能困住自己 | 洪水填充空间评估可大幅降低概率；即使发生也只会触发正常 gameOver |
| 洪水填充在极端密集场景下评估不精确 | 不影响安全性（AI 不会走入炸弹或墙壁）；仅在极罕见场景下可能不够"聪明" |
| 误触方向键意外退出挂机 | 按 H 键即可重新开启；影响极小 |
| `result` 字段 `:auto` 后缀格式未知 | `endsWith(':auto')` 检测，旧记录不带后缀完全兼容 |

## Migration Plan

- **部署**：修改 `index.html`，浏览器刷新即生效。无构建工具，无版本依赖。
- **回滚**：还原 `index.html` 到修改前版本，浏览器刷新。
- **数据迁移**：`result` 字段新增可选 `:auto` 后缀，旧 `result` 值（`collision`/`bomb`/`timeUp`/`win`）不变。排行榜渲染通过 `endsWith(':auto')` 兼容新旧格式。无需迁移脚本。
- **开关**：无服务端开关。`autoPlayEnabled` 为内存变量，页面刷新自动重置为 `false`。
