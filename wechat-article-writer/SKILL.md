# 公众号文章写作流程

目标：把“一个模糊主题”稳定产出成“可直接发布/继续润色/进入草稿箱”的公众号文章。

推荐流程：明确目标 → 搜集资料 → 选择写作风格 → 生成正文 → 生成标题与摘要 → 排版优化 → 如用户需要，衔接发布到公众号草稿箱。

## 适用场景

当用户提出以下需求时使用：
- 帮我写一篇公众号文章
- 帮我把这个主题写成微信文章
- 给我一篇自媒体内容/爆款文章
- 根据资料整理成公众号文案
- 给这篇文章起标题、润色、排版
- 把文章写好后再发布到公众号草稿箱

## 核心原则

1. 先澄清再写，不要拿到模糊主题就直接硬写。
2. 优先保证“对目标读者有用”，再追求“像爆款”。
3. 不杜撰事实；涉及功能、数据、价格、发布时间时优先核验。
4. 默认输出中文。
5. 在写作前让用户从预设风格中选择。
6. 若用户已经明确指定语气、结构、读者、平台目标，则以用户要求优先。
7. 写完后默认交付完整文章 + 备选标题 + 摘要 + 排版建议。

## 先收集这些信息

用户信息不足时，优先补齐以下字段；不要一次问得太散，缺什么补什么：

- 主题：这篇文章要讲什么？
- 目标读者：新手、职场人、开发者、创业者、AI 从业者、家长等
- 写作目标：涨粉、转化、科普、观点表达、经验总结、热点解读
- 素材来源：用户提供资料、联网搜索、已有文章改写、采访记录、产品文档
- 文章长度：短文（800-1200）、标准文（1200-1800）、长文（1800-3000）
- 风格：从下方预设风格中选择
- 是否需要标题党强度：保守 / 平衡 / 强吸引
- 是否需要发布：只写内容 / 顺带排版 / 继续发到公众号草稿箱

如果用户只说“写一篇公众号文章”，最少要补：主题、读者、目标、风格。

## 预设写作风格

写作前，主动让用户从以下风格中选 1 个；如果用户不选，则默认使用「风格 B：专业拆解型」。

### 风格 A：故事共鸣型
适合：个人成长、职场经历、产品体验、创业感悟
特点：
- 先用一个场景/故事开头
- 情绪带入强，阅读门槛低
- 强调“我怎么踩坑、怎么想通、怎么做到”
- 结尾有余味，适合引发转发与留言

### 风格 B：专业拆解型
适合：AI 工具、技术教程、方法论、行业分析
特点：
- 结构清晰，信息密度高
- 少空话，重结论和步骤
- 常用结构：结论先行 → 原因拆解 → 实操步骤 → 注意事项
- 最适合作为默认风格

### 风格 C：犀利观点型
适合：热点评论、行业趋势、认知升级、反常识表达
特点：
- 开头直接抛观点
- 用对比、反问、反直觉吸引读者
- 适合制造讨论度
- 注意不要为了冲突而失真

### 风格 D：朋友聊天型
适合：生活方式、效率技巧、工具安利、轻内容分享
特点：
- 语气自然，像在和朋友讲话
- 少术语，少“模板味”
- 可读性强，适合日更账号
- 适合降低 AI 腔

### 风格 E：案例教学型
适合：教程、复盘、拆案例、运营经验
特点：
- 用真实案例串起全文
- 讲背景、动作、结果、复盘
- 易形成“看完就能照着做”的体验
- 对转化和收藏更友好

### 风格 F：清单速读型
适合：技巧合集、工具盘点、避坑指南、资源推荐
特点：
- 标题和结构都强调数字感
- 小节短，节奏快
- 适合移动端快速阅读
- 适合做高打开率内容，但要防止内容过浅

## 默认执行流程

## Step 1：明确任务边界

先判断属于哪一类需求：
- 从零写一篇
- 基于资料整理成文
- 改写/重写已有文章
- 生成标题与摘要
- 只做排版优化
- 写完后继续发布到公众号草稿箱

如果是从零写，先补齐关键信息。
如果是基于资料写，先读取资料并判断是否足够成文。
如果是改写，先明确：保留观点、保留结构，还是完全重写。

## Step 2：资料搜集与核验

当用户没有提供足够素材时，联网搜索并归纳信息。推荐做法：

1. 并行搜索多个来源：官方文档、产品博客、媒体报道、社区讨论、X/Twitter、Reddit、技术论坛。
2. 优先近 1-3 个月资料；若写“趋势总结”，可拉长到近 1 年。
3. 提炼出：
   - 关键事实
   - 新变化/新功能/新数据
   - 争议点
   - 读者最关心的问题
4. 至少做一次事实核验，尤其是：
   - 功能是否真实存在
   - 时间是否过期
   - 数据是否有来源
   - 价格/政策/模型能力是否变化
5. 输出内部工作草稿时，建议先列：
   - 3-7 个关键信息点
   - 文章主论点
   - 可引用案例

如果资料明显不足，应先告诉用户“目前只能写观点稿/经验稿，不能写成强事实型分析”。

## Step 3：搭建文章结构

先产出一个简短大纲，再扩写正文。根据风格选择结构：

### 通用结构模板
1. 开头：用问题、故事、反常识或结果吸引读者
2. 正文第 1 部分：说明为什么这件事值得关注
3. 正文第 2 部分：拆解方法、步骤、案例或核心观点
4. 正文第 3 部分：补充注意事项、误区、限制条件
5. 结尾：总结 + 提炼一句能让人记住的话 + 可选行动号召

### 结构建议
- 教程类：效果展示 → 适用人群 → 步骤教学 → 常见错误 → 总结
- 观点类：观点开场 → 常见误解 → 论据展开 → 反方回应 → 结论升华
- 工具类：痛点开场 → 工具介绍 → 使用场景 → 实操示例 → 是否值得用
- 复盘类：背景 → 做了什么 → 结果如何 → 哪些有效/无效 → 下次怎么做

## Step 4：成文

按用户指定长度输出。若未指定，默认 1200-1800 字。

### 成文要求
- 开头 2-4 段内必须让读者知道“看这篇能得到什么”
- 每一节只讲一个重点
- 尽量多用具体场景、动作、例子，少用空泛形容词
- 不堆砌“首先、其次、最后”造成模板感
- 减少明显 AI 腔，如：
  - “在当今快速发展的时代”
  - “不可否认的是”
  - “值得一提的是”泛滥
- 段落长度适配手机阅读：每段建议 1-4 句
- 关键句可单独成段
- 如果内容偏强转化，仍要先给价值，再做引导

### 长度建议
- 800-1200：观点快评、轻教程、热点短文
- 1200-1800：标准公众号主文
- 1800-3000：深度拆解、长案例、行业分析

## Step 5：生成标题、摘要、导语

默认输出：
- 5 个标题候选
- 1 个摘要（80-120 字）
- 1 段导语/开头引子（可选用于公众号摘要区或转发语）

### 标题生成规则
至少覆盖以下几类，不要 5 个标题全都一个套路：
1. 痛点型：直接打中读者困境
2. 结果型：突出收益、提升、节省时间
3. 反常识型：制造认知冲突
4. 清单型：数字 + 方法/技巧/步骤
5. 场景型：把读者带入一个真实使用情境

### 标题质量要求
- 不要低质夸张，不做明显虚假承诺
- 尽量具体，少写空洞大词
- 优先让读者一眼知道“这篇和我有什么关系”
- 可根据用户要求控制标题党强度：
  - 保守：偏专业、可信
  - 平衡：兼顾传播与可信度
  - 强吸引：更强调冲击力，但不能失真

## Step 6：排版优化

输出适合公众号编辑器的排版建议：

1. 标题下方放 1 句副标题或摘要
2. 全文控制大段密度，每 2-4 段设置一个小标题
3. 重点结论、数字、警告、关键动作可单独成段并加粗
4. 代码、命令、配置项使用代码块或等宽格式
5. 列表内容尽量改成短句 bullet，避免大段并列文本
6. 配图建议至少包含：
   - 封面图
   - 1-2 张步骤/示意图
   - 结尾总结图或观点图
7. 若文章用于 AI/技术类公众号，建议在适当位置加入：
   - 操作截图
   - 对比图
   - 流程图
   - before/after 效果图

## Step 7：交付格式

默认交付顺序如下：

1. 文章标题候选（5 个）
2. 摘要（1 个）
3. 正文（完整可发布版）
4. 排版建议
5. 配图建议
6. 如果用户要求，还可补：
   - 朋友圈转发文案
   - 公众号封面标题
   - 评论区引导语
   - 阅读原文引导语

## Step 8：如需发布到公众号草稿箱

如果用户明确表示“写完后直接发公众号”或“发布到草稿箱”，则在文章定稿后衔接 `wechat-article-publisher`：

1. 先确认用户要发布的是 Markdown 还是 HTML 版本
2. 将最终文章保存为文件
3. 调用发布 skill，把内容发到公众号草稿箱
4. 明确告知用户：只是保存到草稿箱，不会自动正式发表

## 质量检查清单

交付前至少自检一次：

- 这篇文章的目标读者是否明确？
- 开头是否足够快地给出阅读价值？
- 是否存在未经核验的事实性表述？
- 标题是否过度夸张？
- 结构是否顺畅，有没有重复表达？
- 是否有明显 AI 腔、套话、废话？
- 是否适合手机端阅读？
- 是否给出了读者能立即采取的动作/启发？

## 不同任务的处理分支

### 分支 A：用户只给一个主题
做法：
- 先补齐读者、目标、风格、长度
- 不要急着写整篇

### 分支 B：用户给了素材链接/文档
做法：
- 先提炼素材要点
- 再决定适合写成教程、观点稿还是案例稿

### 分支 C：用户给了一篇旧文让你改
做法：
- 先问清楚是“轻改”“重写”“保留核心观点后重构”
- 保留用户原有亮点，不要整篇洗成统一 AI 风格

### 分支 D：用户要爆款标题，但正文一般
做法：
- 先提醒：标题只能提高打开率，正文决定转发和关注
- 必要时顺手优化开头和小标题

### 分支 E：用户要热点快写
做法：
- 强调时效性
- 先核对事实与时间线
- 允许先出短版，再扩写完整版

## 建议的默认提问模板

当信息不够时，可直接这样问：

“我可以直接帮你写，但为了成稿更像你要的效果，你先告诉我这 4 个信息：
1. 主题是什么？
2. 主要写给谁看？
3. 想达成什么目标（涨粉/转化/科普/表达观点）？
4. 想用哪种风格？可选：故事共鸣型 / 专业拆解型 / 犀利观点型 / 朋友聊天型 / 案例教学型 / 清单速读型。”

## 示例

用户请求：
```text
帮我写一篇关于 Claude Code 使用技巧的公众号文章，读者是刚开始接触 AI 编程的人，目标是涨粉，风格用专业拆解型。
```

推荐执行：
1. 搜索 Claude Code 最新功能、常见使用场景、用户吐槽与最佳实践
2. 提炼适合新手的 3-5 个核心技巧
3. 采用“痛点开场 → 为什么值得学 → 5 个技巧 → 常见误区 → 总结”的结构
4. 输出 1200-1800 字正文
5. 生成 5 个标题 + 1 个摘要 + 排版建议
6. 如用户继续要求，再保存为 Markdown 并衔接发布到公众号草稿箱

## 失败与兜底策略

- 找不到足够可靠资料：明确告诉用户当前更适合写“经验稿/观点稿”，避免伪装成事实分析
- 用户需求过宽：缩小主题，先聚焦一个问题
- 用户又要深度又要超短篇：提醒目标冲突，建议拆成短文版和长文版
- 标题无法兼顾专业和传播：给两组版本，让用户二选一
- 用户没有给风格：默认使用“专业拆解型”，同时说明可切换

## 一句话总结

这个 skill 的目标不是“立刻生成一篇看起来像文章的文字”，而是稳定产出“有读者、有结构、有传播力、能继续发布”的公众号内容。
