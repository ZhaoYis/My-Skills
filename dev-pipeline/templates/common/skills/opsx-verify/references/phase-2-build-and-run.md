# Phase 2：构建 + 启动

## 目标

按项目基准把变更构建出来并启动到可验证状态，命令一律从基准解析，不写死技术栈。

## 执行步骤

1. **解析项目基准命令**
   - 优先读取 `openspec/config.yaml`；回退顺序：`AGENTS.md` → `CLAUDE.md` → README → 脚本启发式（如项目内的构建/启动脚本）。
   - 需要确认的命令：构建、启动 / 运行、（如适用）依赖准备。
   - 该解析逻辑与 `opsx-dev-pipeline` Phase 3「项目基准」加载、Phase 4 verify 命令解析共用同一套描述，不另立标准。

2. **构建**
   - 执行解析出的构建命令，记录：命令、退出码、失败时的关键日志片段。
   - 构建失败：按 `assets/pass-criteria.md` 的失败回路处理，先修复再回到本步骤。

3. **启动 / 运行到可验证状态**
   - 执行启动命令，确认服务 / 程序 / 任务进入可被验证的状态。
   - 记录启动方式与访问入口（如本地地址、CLI 入口、产物路径），供 Phase 3 使用。

4. **无法唯一确定命令时**
   - 若基准给不出唯一命令、存在多个合理候选：列出候选并请用户确认，不擅自猜测。

## 输出要求

- 已确认并执行的构建/启动命令及其结果。
- 可供 Phase 3 使用的验证入口信息。

## Guardrails

- 不写死任何具体构建/运行工具名；一律"按项目基准"表述与执行。
- 命令不可发现或不唯一时请用户确认，不静默选择。
- 失败时进入失败回路，不直接判定整体验证失败。
