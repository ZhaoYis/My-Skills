# Phase 4：影响面回归

## 目标

确认本次变更没有破坏受影响的上游调用方与下游依赖，把验证从"改对了"扩展到"没改坏别的"。

## 执行步骤

1. **确定回归范围**
   - 从 Phase 1 验证目标中的"影响面"维度取上游调用方与下游依赖。
   - 复用 `opsx-design` 改动影响汇总表中的"受影响项"；其中标注的"不受影响项"作为回归边界，原则上不需回归。

2. **执行回归**
   - 优先运行项目基准中的测试命令（按 `openspec/config.yaml` → `AGENTS.md` → `CLAUDE.md` → README 解析），覆盖受影响范围。
   - 测试命令无法唯一确定时，列出候选请用户确认，不擅自猜测。
   - 对没有自动化覆盖的影响面，给出人工回归清单。

3. **记录结果**
   - 记录回归命令、退出码、失败用例与关键日志片段。

## 输出要求

- 受影响范围的回归结果（通过 / 不通过 + 证据）。
- 未被自动化覆盖部分的人工回归清单。
- 一句话整体验证结论（结合 Phase 2/3/4），并对照 `assets/pass-criteria.md`。

## Guardrails

- 回归范围以影响面分析为准，避免漏回归也避免全量盲测。
- 失败时进入 `assets/pass-criteria.md` 的失败回路，不直接判定结束。
