# 不明确点分类（通用）

识别需求歧义时，按以下类别逐项扫描。每类给出判别提示。

| 类别 | 判别提示 | 示例方向 |
|------|---------|---------|
| 交互不明确 | 触发方式、操作路径、前后状态未说清 | 谁触发、在哪触发、触发后看到什么 |
| 规则边界 | 阈值、上限、默认值、取舍规则缺失 | 上限是多少、是否可配置、超限怎么办 |
| 数据来源 | 数据从哪来、口径、更新时机不明 | 取哪个源、实时还是快照、谁维护 |
| 异常场景 | 失败 / 超时 / 并发 / 空数据未定义 | 失败如何提示、是否重试、空态如何展示 |
| 字段含义歧义 | 同名不同义、单位/格式不明 | 字段单位、枚举取值、可空性 |
| 覆盖盲区 | 需求只覆盖主路径，分支/角色未提 | 其他角色、其他入口、历史数据如何处理 |
| 输入无法解析 | 给的资料本身读不懂或自相矛盾 | 两处描述冲突、术语未定义 |

## 使用方式

- 对每一类问自己："这次需求里有没有这类不明确？"
- 命中的写入不明确点清单，并记录关联位置。
- 能从现有上下文（知识库/文档/实现）确定的不算不明确点。
