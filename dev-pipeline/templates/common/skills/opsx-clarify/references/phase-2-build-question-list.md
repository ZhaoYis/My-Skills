# Phase 2：生成澄清问题清单

## 目标

把 Phase 1 的不明确点转成一份具体、可回答、带优先级的问题清单，可直接发给产品 / 干系人。

## 执行步骤

1. **逐条转成具体问题**
   - 每个不明确点写成一个**具体可回答**的问题。
   - 反例："这个功能怎么做？" 正例："导出上限 50 万条是否可配置？默认值是多少？"

2. **标优先级**
   - `P0 阻塞`：不回答就无法继续设计/实施。
   - `P1`：影响实现质量但可先并行推进。

3. **标关联功能与关联位置**
   - 关联功能：问题属于哪个功能点。
   - 关联位置：对应需求/PRD/代码中的位置，便于对方定位。

4. **套用模板**
   - 按 `assets/question-list-template.md` 组织成表格。

5. **自检**
   - 每个问题是否具体可回答？是否标了优先级与关联位置？是否在猜测答案？是否替用户做了决策？任一不满足则修订。

## 输出要求

- 一份符合 `assets/question-list-template.md` 的问题清单。
- 问题按优先级可排序，P0 在前。

## Guardrails

- 不写空泛、无法直接回答的问题。
- 不在问题里夹带预设答案或替干系人拍板。
- 同一不明确点不重复成多条问题。
