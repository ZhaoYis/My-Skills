# Apply 质量门禁（写前复用 + 准出自审查）

> 本文件是 Phase 2（`references/phase-2-apply.md` 步骤 6）的支撑专题，提供**语言 / 框架无关**的「写前复用搜索清单」与「标记完成前自审查清单」。这里只承载清单与判定准则，不重新定义 Phase 主流程；与「项目基准」相关的规范权威仍以 `openspec/config.yaml` → `AGENTS.md` → `CLAUDE.md` 及本仓库既有实现为准（加载顺序见 Phase 3 步骤 8 与 `recovery-guardrails-appendix.md` §2.5）。

## 1. 写前复用门禁（每个任务动手前必做）

目标：先复用、再新建，避免重复造轮子。

### 1.1 检索范围

动手实现前，先在仓库内检索是否已有功能相近的实现，至少覆盖：

- 同类**函数 / 方法 / 模块 / 包**
- 可复用的**工具 / 辅助库 / 公共组件**
- 既有的**类型 / 接口 / 数据结构 / 契约定义**
- 既有的**常量 / 配置 / 枚举 / 错误码**
- 相邻目录中处理**同一业务概念**的实现

### 1.2 检索手段（按项目语言选对应方式）

- 用项目语言对应的检索手段定位符号与用法（如全局符号搜索、文本检索、引用查找等）；不写死某一种工具。
- **可选增强**：若启用了 `structural-analysis-hint`（见 `assets/structural-analysis-hint.md`，默认关闭）且仓库已配置结构化检索能力（代码图谱 / LSP / 索引型 MCP），结构性问题（谁调用谁、符号定义在哪、改动影响面）优先用之替代纯文本检索；纯文本检索用于关键字与字面量匹配。诚实标注盲区与 fallback。

### 1.3 判定与处理

- **命中相近实现** → 优先复用 / 扩展，并在实施说明中标注被复用的引用路径；除非有明确理由（语义不符、耦合过重、契约不同），不重复实现。
- **未命中** → 再新建；新建时保持与相邻实现一致的命名、分层、错误处理与测试风格。
- **部分命中（需改造）** → 评估「扩展既有」与「新建」的成本与影响面，倾向扩展既有，除非会破坏既有调用方。

准则：不造重复轮子；复用决策与引用路径应可被审查者复核。

## 2. 准出自审查门禁（标记任务 `[x]` 前必做）

逐条对照确认；**有一条不满足即不得标记完成**，先改到满足。判断不清时用 AskQuestion（不可用时用编号选项）向用户确认，不要静默放过。

| # | 自审查项 | 通过判据 |
| --- | --- | --- |
| 1 | 正确性 | 实现满足任务描述与提案意图，核心路径行为正确 |
| 2 | 边界与空值 | 处理了空 / 缺省 / 越界 / 极端输入，无明显未覆盖分支 |
| 3 | 错误处理 | 失败路径有明确处理与反馈，不吞异常、不留裸错误 |
| 4 | 复用与去重 | 已执行写前复用门禁；无与既有实现重复的逻辑 |
| 5 | 命名一致 | 命名与相邻代码、领域术语一致，无误导性名称 |
| 6 | 结构 / 分层一致 | 与项目既有分层、模块边界、调用方向一致，未引入新范式 |
| 7 | 与项目基准一致 | 符合 `openspec/config.yaml` / `AGENTS.md` / `CLAUDE.md` 及既有风格 |
| 8 | 资源与副作用 | 正确释放资源、关闭句柄，无未受控的全局副作用或泄漏 |
| 9 | 契约 / 接口一致 | 对外接口、字段、错误语义与调用方 / 既有契约一致 |
| 10 | 安全与敏感信息 | 无硬编码凭据 / 密钥，无明显注入 / 越权 / 不安全默认 |
| 11 | 可读性 | 关键意图清晰；仅在表达非显而易见的意图 / 取舍 / 约束处加注释 |
| 12 | 测试随附 | 按项目习惯补充 / 更新对应测试；说明未补测的合理原因 |

> 说明：本清单是**准出条件**而非加分项。它与「项目基准」是复用关系——基准定义「应遵循什么规范」，本清单定义「标记完成前必须逐条确认到位」，不重复展开各语言细则。
