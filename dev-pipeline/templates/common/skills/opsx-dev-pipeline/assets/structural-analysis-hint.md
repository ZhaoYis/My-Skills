# 结构化代码分析优先指引（可选 · 默认关闭）

> **可选增强**。对应 `config/features.json` 的 `structural-analysis-hint`（默认 `false`）。**未启用时本指引不生效，按纯文本检索的主流程进行，不影响任何 Phase。** 启用后，下述策略作为「探索上下文」环节的优先建议；本文件不绑定任何具体工具 / MCP 名称，只描述策略与 fallback。

## 适用前提

仅当目标仓库**已配置**某种结构化检索能力时启用，例如：

- 代码图谱 / 调用图（code graph）
- 语言服务（LSP：定义跳转、引用查找、符号搜索）
- 索引型检索 MCP / 服务

若以上都不可用：直接走纯文本检索（grep / 全局搜索）的默认路径，并诚实标注这是文本启发式结果。

## 优先级策略

| 问题类型 | 优先手段 | 说明 |
| --- | --- | --- |
| 结构性问题（谁调用谁、改动影响面、符号定义在哪、继承/实现关系） | 优先结构化检索 | 结构化能力对关系型查询更准、更全 |
| 文本性问题（关键字、字面量、配置值、文案、TODO） | 纯文本检索 | 文本匹配足够且更直接 |
| 混合问题 | 先结构化定位入口，再文本补全细节 | 二者互补 |

## fallback 与诚实标注

1. 结构化能力调用失败或结果可疑 → 回退到文本检索，并标注「结构化检索不可用，以下为文本启发式结果」。
2. 结构化与文本结果冲突 → 以可复核的证据（定义位置、引用列表）为准，并说明分歧。
3. 任何无法覆盖的范围 → 显式标注「盲区」，不臆断。
