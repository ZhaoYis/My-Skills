# Phase 3：拆解功能点 / 能力点

## 目标

把需求拆解成便于逐项分析的能力点或功能点，避免在一个混合描述里同时讨论过多变化。

## 执行步骤

1. 根据需求目标与探索证据，拆出独立功能点。
2. 对每个功能点标注：
   - 解决什么问题
   - 是否已有类似能力可复用
   - 是否需要新增行为，还是修改现有行为
3. 若某个功能点仍依赖关键未决问题，单独标记。
4. 确保拆解后的粒度适合进入影响面分析。

## 输出要求

至少给出：
- 功能点 / 能力点列表
- 每个功能点的简短说明
- 每个功能点与现有能力的关系
- 待确认的功能点前提

## Guardrails

- 不要把多个不相干变化强行塞成一个功能点。
- 粒度不宜过粗，也不需要细化到实现步骤级别。
- 功能点拆解应服务于后续影响面分析，而不是写成实施设计。
