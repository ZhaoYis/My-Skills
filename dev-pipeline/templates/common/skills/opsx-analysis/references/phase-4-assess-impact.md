# Phase 4：评估影响面与约束

## 目标

基于已拆解的功能点，分析需求会影响哪些模块、接口、配置、文档、测试或集成边界。

## 执行步骤

1. 对每个功能点逐项分析可能影响：
   - 命令 / 接口 / 入口
   - 模块 / 流程 / 规则
   - 配置 / 状态 / 数据
   - 测试 / 文档 / 运维脚本
   - 外部依赖 / 集成边界（如有）
2. 判断是否存在可复用现有实现，或必须引入新行为。
3. 记录显式约束：
   - 兼容性要求
   - 现有流程限制
   - 已知风险
   - 缺失上下文
4. 把不确定但重要的问题整理为待确认项。

## 输出要求

至少给出：
- 每个功能点的影响面
- 可复用与需变更的现有能力
- 关键约束条件
- 风险与待确认项

## Guardrails

- 影响面分析不等于实现方案设计。
- 优先基于证据判断影响，而不是从常见经验泛化。
- 若证据不足，应诚实标记不确定性。
