# Phase 1：明确需求目标与边界

## 目标

把“要分析什么、这次分析覆盖到哪里、什么暂不纳入”先定义清楚，为后续探索和判断建立边界。

## 执行步骤

1. 识别用户输入属于哪一类：
   - 新需求描述
   - 变更需求
   - 文档 / PRD / issue 片段
   - 业务补充说明
   - 已有分析结果的补充修订
2. 判断当前输入是否具备可分析边界：
   - 目标是否单一
   - 范围是否可控
   - 是否已有明确入口或场景
   - 是否存在明显超出本轮分析范围的问题
3. 若范围过大，帮助用户收缩为一个可分析单元。
4. 若范围过小，补齐最小必要上下文。
5. 与用户确认本轮分析目标，以及暂不覆盖的边界。

## 输出要求

至少给出：
- 本轮分析目标
- 当前范围（做什么 / 不做什么）
- 现有输入来源
- 关键不确定项
- 下一步准备探索的上下文来源

## Guardrails

- 不要在范围未清晰前直接开始影响面结论。
- 若用户说“整体分析一下”，优先拆成第一个最需要确认的分析单元。
- 若同一请求混入多个主题，先帮助用户明确优先级。
