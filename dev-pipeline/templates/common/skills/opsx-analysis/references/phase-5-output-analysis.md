# Phase 5：输出结构化分析结果

## 目标

把探索与分析结果整理成可讨论、可决策、可继续推进的结构化输出。

## 执行步骤

1. 按 `assets/analysis-output-template.md` 组织默认输出结构。
2. 明确区分：
   - 已确认事实
   - 基于证据的推断
   - 待确认问题
3. 若用户只要简版分析，可保留核心结论；若要求完整分析，则按模板全量输出。
4. 默认在对话中输出，不主动写文件。
5. 若用户要求落盘，再确认目标位置与格式。

## 输出要求

默认至少包含：
- 需求摘要
- 范围界定
- 功能点拆解
- 影响面分析
- 风险与待确认项
- 建议下一步

## Guardrails

- 不要把分析结果伪装成已确认方案。
- 若没有足够证据，不输出过度确定的结论。
- 分析结果应帮助用户做下一步决策，而不是替代用户做全部决策。
