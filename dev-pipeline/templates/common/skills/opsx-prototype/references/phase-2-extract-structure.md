# Phase 2：抽取界面 / 组件 / 交互 / 数据结构

## 目标

把原型素材转成结构化要素，为后续需求分析提供清晰、可核对的输入。

## 执行步骤

1. **界面（页面 / 视图）**
   - 列出涉及的页面 / 视图及其用途与入口关系。

2. **组件 / 控件**
   - 每个页面上的关键控件（表单、列表、按钮、筛选、弹窗等）及其作用。

3. **交互**
   - 触发动作 → 反馈 / 跳转 / 状态变化；标注主路径与分支。

4. **数据**
   - 界面上呈现 / 录入的数据字段；推断其来源与口径（标为"推断"，待确认）。

5. **状态**
   - 加载 / 空态 / 错误 / 权限不足等状态在界面上的表现（截图未覆盖的列为待确认）。

6. **标注确定性**
   - 区分：界面上明确可见的事实 vs 基于经验的推断 vs 需用户确认的空白。

## 输出要求

- 按界面 / 组件 / 交互 / 数据 / 状态归类的结构化要素。
- 每类中明确区分"可见事实 / 推断 / 待确认"。

## Guardrails

- 不把推断当事实；推断必须标注。
- 截图 / 描述未覆盖的分支不要补全成"看起来应该有"，列为待确认。
- 数据来源除非用户说明，否则只作推断并标注。
