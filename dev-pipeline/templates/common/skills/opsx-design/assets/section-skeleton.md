# 通用章节骨架（语言 / 领域无关）

按下列顺序考虑每一节。标"仅当有"的章节只有真实存在时才写，否则整节删除。每节开头标注受众：`[实现者]` / `[前端/调用方]` / `[测试]`。

## 1. 概述与数据流
- 这次要做什么、解决什么问题。
- 数据从哪来 → 如何处理 → 如何输出。

## 2. 影响范围与改动清单
- 文件级改动列表（套用 `impact-summary-template.md`）。
- 分"受影响"与"不受影响"两个分区，**不受影响区至少 1 项**。

## 3. 接口 / 契约变更（仅当有）
- 新增接口：列完整字段（名称、类型、含义、约束、是否必填）。
- 修改接口：只列变更字段与兼容性影响。

## 4. 数据 / 存储变更（仅当有）
- 新增 / 修改的数据结构、存储项、迁移方式与回滚考虑。

## 5. 复用与风险分析
- 可复用的现有实现（模块 / 接口 / 工具）。
- 风险按 高 / 中 / 低 分级，每条给出应对方向。

## 6. 关键流程图 / 时序图（仅当涉及多方交互）
- 用文字或 ASCII / mermaid 描述主链路与分支。

## 7. 异常场景设计（仅当有）
- 每个异常：触发条件 → 处理方式 → 对外表现。

## 8. 验证断言字段（供 opsx-verify 使用）
- 每个关键行为一条：`断言字段` + `数据来源` + `判定方式（自动 / 人工）`。

## 9. 任务清单
- 每条任务对应一个文件变更；一任务改多文件则拆分。
- 命令 / 构建 / 测试统一表述为"按项目基准"。
