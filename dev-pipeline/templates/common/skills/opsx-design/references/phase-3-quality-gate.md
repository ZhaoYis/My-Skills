# Phase 3：质量自检门禁

## 目标

在交付设计之前，用统一的质量门禁逐条自检，把"看起来完整"的设计提升为"实现者能照做、验证者能验收"的设计。

## 执行步骤

1. 打开 `assets/quality-checklist.md`，逐条核对。
2. 任一条不通过，回到 Phase 2 修订对应章节后再次自检。
3. 全部通过后，给出一句话门禁结论（通过 / 不通过 + 原因）。

## 门禁要点（详见 `assets/quality-checklist.md`）

- **相关性过滤**：每节自问"去掉这节，实现者还能否正确实现？"能 → 删。
- **受众标注**：每节都标了 `[实现者]/[前端/调用方]/[测试]`，且内容只写给标注读者。
- **边界完整性**：改动影响汇总表**至少含 1 个"不受影响"项**；否则视为漏了边界分析，必须补。
- **任务粒度**：tasks 每条对应一个文件变更；一任务改多文件则拆分。
- **可验证性**：必含验证断言字段（断言字段 + 数据来源 + 自动/人工），与 `opsx-verify` 联动。
- **通用化**：全文无写死技术栈词；命令均"按项目基准"。

## 失败处理

- 门禁不通过时，**不得**宣称设计已完成。
- 明确列出未通过的条目与缺什么，回到 Phase 2 修订，循环直到全部通过或用户主动收窄范围。

## 输出要求

- 一份逐条标注通过/不通过的自检结果。
- 门禁通过后的最终设计，可独立交付或喂给 `opsx-verify`。
