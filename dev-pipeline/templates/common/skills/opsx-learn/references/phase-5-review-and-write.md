# Phase 5：审核、确认并沉淀

## 目标

让用户对候选知识条目做最后确认，并把确认后的知识写入正确位置。

## 执行步骤

1. 按条目或分组向用户展示候选知识：
   - 保留
   - 修改
   - 跳过
2. 若用户同意落盘，先确认写入位置：
   - 现有知识目录
   - `.knowledge/`
   - `docs/knowledge/`
   - 其他项目约定目录
3. 按 `assets/dedup-rules.md` 执行去重 / 合并判断。
4. 采用追加或局部合并方式沉淀知识，不直接覆盖既有内容。
5. 汇总本次新增 / 更新 / 跳过的条目。

## 输出要求

最终应明确：
- 哪些条目被保留
- 哪些条目被修改后保留
- 哪些条目被跳过
- 写入到了哪里
- 后续仍待补充的知识空白

## Guardrails

- 若用户未批准，不得自行写入。
- 若写入目标不明确，必须停下来确认。
- 若检测到高重合内容，优先补充已有条目，而不是重复创建。
- 若用户要求“先不写入”，则输出审核后的最终草稿与建议写入位置即可。
