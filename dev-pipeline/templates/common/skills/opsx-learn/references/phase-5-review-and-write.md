# Phase 5：审核、确认并沉淀

## 目标

让用户对候选知识条目做最后确认，并把确认后的知识写入正确位置。

## 执行步骤

1. 按条目或分组向用户展示候选知识：
   - 保留
   - 修改
   - 跳过
2. 先结合 `scripts/opsx-learn-preflight.sh` 的结果判断是否已有既定知识目录。
3. 若预检结果中包含 `knowledgeHealth`，在真正写入前先检查其中的 `warn` / `fail` 项，并优先直接引用 `knowledgeHealthSummary` 与 `knowledgeHealthHighlights` 向用户提示；必要时再展开原始检查明细：
   - `.knowledge` 骨架是否缺失
   - `INDEX.md` 是否缺关键 section
   - `INDEX.md` 是否仍停留在大量占位符状态
   - 是否存在 manifest 与知识骨架漂移
4. 若是首次使用且仓库中不存在明显知识目录，必须明确提示用户确认写入位置；默认建议 `.knowledge/`。
5. 若用户同意落盘，确认最终写入位置：
   - 现有知识目录
   - `.knowledge/`
   - `docs/knowledge/`
   - 其他项目约定目录
6. 按 `assets/dedup-rules.md` 执行去重 / 合并判断。
7. 若本次新增或修订内容会影响索引入口，同步检查并更新 `.knowledge/INDEX.md`（或项目既有知识索引文件）。
8. 采用追加或局部合并方式沉淀知识，不直接覆盖既有内容。
9. 汇总本次新增 / 更新 / 跳过的条目。

## 输出要求

最终应明确：
- 哪些条目被保留
- 哪些条目被修改后保留
- 哪些条目被跳过
- 写入到了哪里
- 是否同步更新了索引，以及更新了哪些索引项
- 后续仍待补充的知识空白

## Guardrails

- 若用户未批准，不得自行写入。
- 若写入目标不明确，必须停下来确认。
- 若检测到高重合内容，优先补充已有条目，而不是重复创建。
- 若用户要求“先不写入”，则输出审核后的最终草稿与建议写入位置即可。
