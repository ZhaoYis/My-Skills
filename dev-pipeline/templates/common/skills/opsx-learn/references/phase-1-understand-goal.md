# Phase 1：明确目标与边界

## 目标

把“想学什么、为什么学、这次覆盖到哪里”定义清楚，为后续追踪、提炼和沉淀建立稳定边界。

## 执行步骤

1. 识别用户输入属于哪一类：
   - API / 路径
   - 方法 / 类 / 模块
   - 功能描述
   - 文档 / 需求片段
   - 业务域 / 问题域
   - 既有知识条目的补充 / 修订
2. 判断当前输入是否已经具备可执行边界：
   - 目标是否单一
   - 范围是否可控
   - 是否有明确入口
   - 是否有明显超出本轮范围的关联问题
3. 若范围过大，主动收缩为一个可执行的学习单元，例如：
   - 一个接口
   - 一个功能闭环
   - 一个模块中的一条关键链路
   - 一条待修订的既有知识
4. 若范围过小且无法形成稳定认知，适度向上补齐最小必要上下文。
5. 与用户确认本轮只处理一个清晰目标，并说明暂不覆盖的边界。

## 输出要求

至少给出：
- 本轮学习目标
- 学习入口
- 本轮边界（包含“做什么 / 不做什么”）
- 需要特别关注的风险点或不确定项
- 下一步准备定位的入口

## 判断标准

进入下一阶段前，应满足：
- 目标足够具体，可以开始定位入口
- 范围足够收敛，不会扩散成全仓漫游
- 至少有一个可追踪的入口对象
- 用户对当前边界没有明显异议

## Guardrails

- 不要在范围未确认前直接开始大面积搜索。
- 若用户表达的是“想整体了解系统”，先帮助其拆成首个最值得学习的子目标。
- 如果同一请求同时包含多个入口，优先让用户确认优先级。
- 不要把“顺手可查”的旁支问题混入本轮主目标。
- 若用户目标本质上是排障、开发或重构，而不是沉淀知识，应先指出当前 skill 的定位，再决定是否只保留知识提炼部分。
