# Phase 3：追踪实现链路

## 目标

从入口出发，梳理关键调用链、依赖边界、数据流和业务规则来源。

## 执行步骤

1. 从主入口向下追踪核心调用链。
2. 记录关键节点：
   - 输入校验 / 参数转换
   - 业务决策点
   - 数据读取 / 写入
   - 外部依赖或三方服务
   - 错误处理与回退逻辑
3. 找出对理解业务真正关键的测试、脚本或文档。
4. 对于不确定的业务意义，明确标注“代码事实”和“待用户确认解释”。

## 输出要求

至少整理出：
- 主链路步骤
- 关键依赖点
- 涉及的数据对象 / 配置 / 状态
- 已确认的事实
- 待确认的业务解释

## Guardrails

- 不要求把所有实现细节都写成知识；重点是后续最值得复用的认知。
- 不要把猜测包装成结论。
- 如果链路过深，优先保留能解释行为的关键节点，省略机械性细节。
