# Phase 4：提炼知识草稿

## 目标

把追踪结果转成结构化、可复用、可审核的知识草稿。

## 执行步骤

1. 按知识类型整理条目，例如：
   - 功能闭环 / 流程说明
   - API / 接口约定
   - 业务规则
   - 数据模型 / 存储约束
   - 外部依赖 / 集成点
   - 常见问题 / 风险提示
2. 每条草稿都附上来源依据：文件、函数、文档、测试等。
3. 对不完整但有价值的结论，显式标记“待确认”或“假设”。
4. 参考 `assets/knowledge-entry-templates.md` 统一格式。

## 输出要求

至少产出：
- 候选知识条目列表
- 每条条目的摘要
- 关键来源
- 建议写入的知识分类

## Guardrails

- 一条知识只表达一个核心认知，避免多个结论混写。
- 若草稿内容过长，拆分为更小条目，便于用户审核。
- 若现有知识库已有相同主题，先标记为“候选补充”，不要直接新建重复条目。
