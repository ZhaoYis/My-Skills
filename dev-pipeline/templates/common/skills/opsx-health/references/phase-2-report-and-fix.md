# Phase 2：生成报告 + 修复建议 + 可选执行修复

## 目标

把 Phase 1 的检查结果转成一份可读的健康报告，给出按 P0–P3 排序的修复建议，并在用户确认后可驱动修复。

## 执行步骤

1. **生成报告**
   - 套用 `assets/report-template.md`：总体状态/评分、按维度的问题（断链 / 重复 / 老化 / 索引 / 占位）、趋势（若有 `--history`）。

2. **分级修复建议**
   - 对每个问题给出修复建议，并按优先级排序：
     - `P0`：导致检索/使用失效（如断链、索引缺失）。
     - `P1`：明显影响质量（如重复条目、空占位）。
     - `P2`：维护性问题（如老化超阈值、待修订）。
     - `P3`：优化建议（如结构/命名一致性）。
   - 每条建议写清：问题、影响、建议动作、涉及文件。

3. **可选执行修复（需用户确认）**
   - 修复是写操作，**必须先经用户确认**，不静默修改。
   - 执行修复时，涉及知识库写入的部分遵循同级 `opsx-learn` 的约定：
     - 写入目标：`../../opsx-learn/assets/write-targets.md`
     - 去重规则：`../../opsx-learn/assets/dedup-rules.md`
     - 条目格式：`../../opsx-learn/assets/knowledge-entry-templates.md`
     - 无该技能时按通用落位，仅追加不覆盖，并同步 `.knowledge/INDEX.md`。
   - 修复后复跑 Phase 1 的 doctor 确认问题是否消除。

## 输出要求

- 一份结构化健康报告。
- 一份按 P0–P3 排序的修复建议。
- 若执行了修复：修复摘要 + 复检结果。

## Guardrails

- 任何写操作前必须用户确认。
- 不覆盖用户手工维护内容；仅追加并标注来源/时间。
- 降级模式下应说明哪些维度未能检查。
