# 通用代码审查清单（Convention Checklist）

> 本清单与具体语言/框架无关。所有"强制"检查项均以项目基准（Project_Baseline）解析到的规范为准。
> 本文件是 `git-code-review` 与 `file-code-review` 两个技能共享清单的**唯一权威来源**，请勿在技能正文中内联复制本清单内容。

## 1. 规范来源解析（强制）

- 按 Project_Baseline 顺序解析规范来源，命中即用：
  1. `openspec/project.md`（主基准）
  2. `README.md`
  3. `CLAUDE.md`
  4. `AGENTS.md`
  5. 邻近架构文档（如 `docs/`、`ARCHITECTURE.md` 等）
  6. 通用约定兜底（以上均未找到时）
- 在审查报告中记录实际解析到的规范基准来源（`规范基准` 字段）。
- 若未找到任何项目基准来源，须在报告中明确记录"未找到项目基准"，并采用通用约定继续审查。

## 2. 通用审查维度（强制，语言无关）

| 维度 | 检查要点 |
| ---- | -------- |
| 命名一致性 | 是否遵循项目基准中声明的命名约定 |
| 分层/模块边界 | 是否符合项目基准声明的架构边界，无反向/跨层依赖 |
| 错误处理 | 错误路径是否被处理并向上传递，无静默吞错 |
| 日志 | 使用项目约定的日志机制，无裸输出（如 print/console/标准输出直写） |
| 安全 | 输入校验、注入防护、鉴权/授权按基准要求 |
| 敏感信息 | 无硬编码密钥/口令/令牌（见密钥扫描步骤） |
| 性能 | 无明显的 N+1、重复计算、未释放资源 |
| 测试 | 关键变更具备对应测试或验证手段 |

## 3. 严重程度判定（强制）

| 严重程度 | 图标 | 判定标准 |
| -------- | ---- | -------- |
| 严重 | 🚨 | 安全漏洞、Bug、破坏性变更、敏感信息泄露 |
| 重要 | ⚠️ | 规范违规、性能问题、设计原则违反 |
| 一般 | 📝 | 代码风格、命名、注释 |
| 建议 | 💡 | 最佳实践、优化建议 |
