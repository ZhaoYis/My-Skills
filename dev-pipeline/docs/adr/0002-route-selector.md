# ADR 0002 — 三档 Route 选择器实现风险分级流水线

- **状态**：已采纳
- **日期**：2025-08-28
- **范围**：工作流设计

## 背景

琐碎的变更（错别字修复、import 清理）和数据库迁移变更今天走的是同一套
OpenSpec 流程。这意味着修复一行 README 也要经历 proposal → apply →
review → 单测 → archive → commit → push。开销是真实存在的：审查者会为
空白行变更被打扰，CI 会为 import 重排跑完整测试套件。

我们希望提供一种**让工作流重量与变更风险匹配**的机制，但又不想让消费
方各自手写门禁。

## 决策

引入三档 **Route** 选择器：

| Route      | 执行的阶段                  | 适用场景                          |
| ---------- | --------------------------- | --------------------------------- |
| `trivial`  | {0, 2, 6}                   | 错别字、格式化、注释              |
| `standard` | {0, 1, 2, 5, 6}             | 新功能、Bug 修复、重构            |
| `full`     | {0, 1, 2, 3, 4, 5, 6, 7}    | 核心逻辑、schema 变更、安全相关   |

规则：

1. Route 在 **Phase 0** 通过一段简短的变更描述提示**选定**，结果作为
   `route.choice` 持久化到流水线状态文件。
2. **只能升级**：`trivial → standard → full`。不允许降级，因为较轻的
   阶段可能已经跳过了较重阶段本应完成的工作（例如测试）。
3. 没有 `route` 字段的旧状态文件默认 `full`，以兼容 ADR-0001 时期的
   老用户。
4. `openspec/config.yaml#pipeline.routes` 是阶段列表的**单一事实源**；
   状态文件只记录**选择了哪一档**，不记录阶段列表本身。

## 影响

**正面**

- 琐碎变更秒级交付；审查者不再被噪音打扰。
- 同一套 Phase 0–7 状态机服务全部三档 Route —— 实现上不分叉。
- Route 升级可审计（记录 `upgradedFrom`、`upgradedAt`）。

**负面**

- Route 选择是启发式的，误判会让 `trivial` 走过于轻量的流程。缓解措施：
   升级路径始终可用。
- 消费方需要学习三档定义与升级规则。已在 README 中说明，并通过 skill
   包里的决策提示暴露给用户。

**中性**

- 本 ADR 不改动 OpenSpec 命令本身 —— 直接调用 OpenSpec 命令时它们仍
   然会无条件执行。门禁位于 `opsx-dev-pipeline` 的 skill 层。

## 备选方案

- **固定全流程**：拒绝，琐碎变更成本过高。
- **可配置阶段列表（用户自由编排）**：拒绝，自由度过高反而导致各团队
  流水线无法对齐，且无法复用审计与升级能力。
