# Structure

## Top-level layout

```
src/         TypeScript source (compiled to dist/)
templates/   Handlebars templates rendered into target projects
config/      Static JSON: tools.json (adapters), features.json (features)
test/        Vitest unit + integration tests
docs/        Reference docs (roadmap, etc.)
dist/        Build output (generated, not edited by hand)
```

## Source organization (`src/`)

- `src/bin/` — executable entry points (`opsx-dev-pipeline.ts`, `create-opsx-dev-pipeline.ts`). Thin wrappers that call into `cli/` and handle top-level errors.
- `src/cli/` — CLI wiring.
  - `index.ts` — registers all commands and options with `cac`.
  - `commands/` — one file per command (`init`, `sync`, `upgrade`, `uninstall`, `doctor`, `list-tools`). Each exports a `run<Name>Command` function.
- `src/core/` — domain logic, grouped by concern. Each subfolder typically owns its own `types.ts`:
  - `adapters/` — AI tool adapter registry and types.
  - `assets/` — asset manifest definitions.
  - `init/` — install pipeline: collect inputs → build plan → resolve conflicts → render → execute.
  - `uninstall/` — uninstall pipeline (build plan → resolve conflicts → execute).
  - `upgrade/` — upgrade-specific version prompts.
  - `manifest/` — read/write the install manifest and version checks.
  - `doctor/` — knowledge-health checks, scoring, and history.
  - `knowledge/` — `.knowledge/` directory helpers.
  - `runtime/` — package root resolution and metadata (e.g. `PACKAGE_VERSION`).
  - `prompts/`, `files/` — shared prompt/file utilities and types.

## Templates (`templates/`)

- `templates/common/` — shared assets: `base/`, `commands/`, `skills/`, `knowledge/`.
- `templates/tools/<tool>/` — per-tool overlays for `claude`, `cursor`, `codex`, `generic`.
- Template files use the `.hbs` extension and are rendered with Handlebars during `init`/`sync`/`upgrade`.

## Tests (`test/`)

- `test/unit/` — unit tests, one file per core module (e.g. `build-install-plan.test.ts`).
- `test/integration/` — end-to-end CLI/package behavior (`init-matrix`, `init-smoke`, `package-artifact`, `single-source-guard`).
- `test/helpers/` — shared test utilities; `test/fixtures/` — test fixtures.
- Naming: kebab-case `*.test.ts` mirroring the module under test.

## Conventions

- New CLI command: add `src/cli/commands/<name>.ts` exporting `run<Name>Command`, then register it in `src/cli/index.ts`.
- New core capability: create a folder under `src/core/<concern>/` with logic plus a local `types.ts`.
- Tool/feature definitions live in `config/tools.json` and `config/features.json`, mirrored by types in `src/core/adapters/types.ts`.
- Keep `dist/` out of manual edits; it is regenerated by `npm run build`.
